# 1.11.7-juntong.2 — DSH 0.2.2 tool-admission compatibility

This fork release targets DSH 0.2.2-rc.3 and retains the guarded keyboard-interactive password authentication from 1.11.7-juntong.1. The npm/plugin identity remains `@lemoncat7/dsh-ssh` to preserve existing configuration and credential scope.

## Fixed

DSH's `system-prompt/assemble` now receives `PromptPresentation`, without a `tools` array. The previous SSH/file visibility listeners read `assembly.tools.filter(...)`, causing every affected AI run to fail with `Cannot read properties of undefined (reading 'filter')`.

SSH and file tools now use `ctx.tools.register(definition, { when })`. Admission is evaluated once per step and applies to declarations, dispatch and programmatic bindings. It is not an optional undefined guard around the old prompt filter. Execution-time session ownership, endpoint authorization and command/file approval remain enforced.

- No SSH mount: ordinary SSH tools are absent.
- Exec mode: one-shot SSH command tools, without interactive terminal or forwarding mutation tools.
- Terminal mode: retained Activity terminal tools, without `ssh_exec`.
- FTP browse-only: endpoint/directory listing and transfer status, without transfer/upload/download mutation tools.
- Mounted SFTP: existing per-endpoint transfer and approval rules remain in force.
- Human-consent temporary-access tools remain available under their existing consent/lease rules.

System-prompt listeners only add contexts, and instructions follow the current step's admitted tool set rather than changing tools in the presentation waterfall.

## Session grants

Existing saved session grants are preserved. DSH 0.2.2-rc.3 ordinary forks do not supply the older `parentSession` linkage. This release does not infer grants from historical lineage or chat text. Mount hosts explicitly in a new/forked session; removing a session grant must not automatically recreate it from a parent.

## Compatibility and validation

The engine and host peer ranges now target `^0.2.2-rc.3`. Type checking uses the updated agent, tools and system-prompt APIs. Admission regressions exercise the real DSH `ToolsService.resolve`, `schemas` and `executable` contracts, including denial before entering implementations. Authentication tests use local test servers with dummy credentials, not real user passwords.

Validation on this Windows host:

- TypeScript compile and client bundle: passed.
- Selected authentication/admission/approval/revocation/prompt regressions: 54 passed, 0 failed (the known local-download fsync case was explicitly excluded from this selection).
- Complete suite with normal permissions: 232 tests, 224 passed, 6 failed, 2 skipped. The six failures are the previously reproduced Windows baseline: four fsync-dependent download cases, one Unix file-mode assertion, and one missing Bash executable. No new full-suite failures were introduced.
- Packed connector bytes match the previously installed authenticated fork exactly.

Native/PTC model executor behavior follows the inspected DSH tool-set contract; the tests exercise real tool admission/lookup but not a live model executor. A real GUI message still needs verification after installation.
